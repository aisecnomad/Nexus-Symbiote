# Finding catalog

A finding (risk) is a security-relevant observation about a single component: its category, severity, detail, and recommendation. Findings describe repository declarations and static evidence—they are not confirmed runtime vulnerabilities. Use these exact category names in `ignore_categories` and [suppressions](policy-reference.md#suppressions).

## How findings affect the gates

`risk` and the scan gate (`scan`, `baseline`, GitHub Action) sum finding weights: **critical 10**, **high 7**, **medium 4**, **low 1**, **info 0**. The aggregate score is an uncapped sum (not a 0–100 percentage) that grows with inventory size.

The gate fails when any of these conditions holds (built-in policy defaults in parentheses):

- A finding meets or exceeds `fail_on_severity` (`critical` in CLI/project policy; `high` by default in the GitHub Action unless `fail-on-severity` overrides it).
- The aggregate score meets or exceeds `fail_threshold` (`50`).
- An `invalid_safetensors` finding is present, regardless of score.
- Coverage is `incomplete` or `unknown`.
- A repository scan finds no agent manifest or supported local inventory evidence.
- Any configured suppression has expired.

Findings excluded by `ignore_categories` or an active suppression do not count toward these checks. See the [policy reference](policy-reference.md) for overrides and the [glossary](glossary.md#risk-level) for how `risk` assigns risk levels.

## Categories

Collector names match `--scanner`. Every collector can emit `identifier_characters` when components merge into the inventory (including the repository agent and `agent.yaml` declarations). `risk` independently re-derives `invalid_safetensors`, `serialization_format`, or `code_execution` when recorded model fields require them (for example in an edited inventory).

### Detailed classification rules

See [known false-positive and false-negative classes](security-model.md#known-false-positive-and-false-negative-classes) for additional heuristics (such as `.bin` inspection and Unicode exemptions).

- **`credential_exposure`**: Reports positions (`env` key, 1-based `argument N`, `header`, `endpoint URL query`, or generic `an env key`/`a header` when the name itself holds or matches a redacted literal) up to 12 listed positions (capped at 64 scanned positions per server); never exports values, prefixes, or lengths. Matches known vendor token formats (excluding placeholders and publishable/anon JWTs), `Authorization`/`Proxy-Authorization` schemes (`Bearer`/`Basic`/etc. ≥8 chars unless placeholder/reference/prose), PEM/PuTTY private keys (raw or base64), URL userinfo passwords, `key=value;` and libpq connection strings, JSON/Cookie/inline-script assignments, shell defaults (`${TOKEN:-literal}`), and credential-shaped values under credential-named keys/flags (including two-argument flags and auth-mode selectors like `--auth bearer <value>`). For registry identifiers, ordinary words ending in `sk` (`desk`, `risk`, `kiosk`, `task`) are preserved unless qualified provider-key evidence is present.
- **`hidden_markup`**: Covers HTML comments, processing instructions, declarations, CDATA, HTML-block comment forms, unused or duplicate Markdown link reference definitions, `#`/`<>` definitions, and unreferenced/duplicate footnotes. Rated **high** when text contains a URL, `~/` path, imperative verb, or `run` targeting a path/script/shell/code-executing command (including after punctuation/markup, `run the following...`, or chained command separators in the same sentence); benign phrases like `run make test`, `dry-run`, or `last run:` remain **low**.
- **`hook_commands`**: Covers Claude Code/Cursor settings hooks, subagent/skill front-matter hooks, `hooks/hooks.json`, plugin-manifest hooks, and Claude Code `statusLine`/`fileSuggestion` commands. Rated **critical** for download (`curl`, `wget`, `iwr`, `irm`, etc.) or `base64 -d/--decode` piped/substituted/saved-and-executed into a shell (`sh`, `bash`, `zsh`, `pwsh`, etc.), `eval`/`source`, or stdin-reading interpreter (`python3 -`, `node`, `perl`, `ruby`, `php`, `lua`)—accounting for quotes, escapes, `${IFS}`, wrappers (`env`, `sudo`, `nohup`, `timeout`, `xargs`, `script`, etc.), and PowerShell `-EncodedCommand` prefixes (`-e`, `-ec`, `-en`, `-enc`) prior to a script path. Rated **high** for URL/downloader-bearing commands; **medium** otherwise.
- **`identifier_characters`**: Replaces C0/C1 controls, ESC sequences, bidi/format chars, CI log-command introducers, and name tabs/newlines before export, and flags intra-word mixed-script lookalikes (e.g., Latin + Cyrillic/Greek) or all-confusable non-Latin words beside Latin (`shell_ехес`) in MCP server/tool names. Emoji variation selectors/ZWJ, IDNA CONTEXTJ joiners, and CJK+Latin words are not flagged. Uncovered fields are listed in [known limitations](known-limitations.md#every-collector).
- **`launch_context`**: Treats `/run` and `/var/run` (and runtime/socket subpaths such as `docker`, `containerd`, `podman`, `dbus`, `crio`, `systemd`, `k3s`, `lxd`, `snapd`) as runtime socket mounts (high), `/proc/<pid>/root` and `/proc/<pid>/cwd` as host root (high), other `/proc` mounts as broad mounts (medium), and code-loading variables/exported bash functions passed via `docker run -e` as medium.
- **`permission_scope`**: Rates risky modes, `enableAllProjectMcpServers`, and credential helpers declared in `.claude/settings.json` even when `.claude/settings.local.json` overrides them (while recording merged values in `permission_mode` / `settings_declarations`). `dontAsk` is not flagged. `Bash` rules strip leading `VAR=val` assignments and executable paths/suffixes; wildcard domains like `WebFetch(domain:**)` count as unscoped. Effective runtime approval remains unverified.
- **`settings_environment`**: **High** covers API/OTLP/AWS endpoint redirects (`*_BASE_URL`, `*_API_URL`, `OTEL_EXPORTER_OTLP_*`, `AWS_ENDPOINT_URL*`), proxies (`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`), TLS/CA overrides (`NODE_EXTRA_CA_CERTS`, `NODE_TLS_REJECT_UNAUTHORIZED`, `SSL_CERT_*`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`), and provider/credential/account switches (`ANTHROPIC_*`, `CLAUDE_CODE_USE_*`, `AWS_*`, `GOOGLE_APPLICATION_CREDENTIALS`). **Medium** covers code-loading variables (`BASH_ENV`, `NODE_OPTIONS`, `LD_PRELOAD`, `PYTHONPATH`, `PATH`), Git/SSH execution hooks (`GIT_SSH*`, `GIT_EXEC_PATH`, `GIT_ASKPASS`, `GIT_TEMPLATE_DIR`, `GIT_CONFIG_*`, `SSH_ASKPASS`), and Claude Code shell/plugin overrides (`CLAUDE_CODE_SHELL*`, `CLAUDE_CODE_GIT_BASH_PATH`, `CLAUDE_ENV_FILE`, `CLAUDE_CODE_PLUGIN_DIRS`).

## Reports that are not findings

- **Collection failures and coverage gaps** are coverage records (no category/severity) that fail gates through completeness; see [glossary](glossary.md#coverage-gap).
- **`validate` issues** (e.g., `unpinned_version`, `weight_files_mismatch`) in `validate --json-output` govern completeness and integrity checks, not risk score.
- **Drift alerts** rate changes between two snapshots; see [what the alerts mean](drift-gate.md#what-the-alerts-mean).
- **`trace-diff` results** compare OTLP traces against an inventory without modifying it (`risk`, `ignore_categories`, and suppressions do not apply). Undeclared/unidentified calls fail `trace-diff` and export as `runtime_undeclared` under `--sarif` ([trace evidence](trace-evidence.md#exit-codes-and-the-gate)).
- **Views (`graph`, `crosswalk`, `minimum-elements`)** summarize recorded evidence rather than adding findings (only `minimum-elements --fail-under` gates on element coverage).

## SARIF rules

Each finding maps to SARIF rule `nexus_symbiote/<category>/<severity>` (a severity change moves the finding to a different rule; see [migration](fingerprint-migration.md#sarif-rule-identifiers)). Findings on ShadowScan-imported components are omitted from SARIF.

Every category above—plus `runtime_undeclared` from `trace-diff --sarif` ([trace evidence](trace-evidence.md#sarif))—has a catalog entry with title and taxonomy tags in [standard exports](standard-exports.md#sarif-for-github-code-scanning) and rationale/regulatory mappings in [framework crosswalk](framework-crosswalk.md). Uncataloged categories (such as from an edited inventory) receive a generic rule tagged only `security`.
