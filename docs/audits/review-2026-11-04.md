Baseline: `main` at `14f2ecf` (#116). Open pull request #118 at `4e61de1`. Continues the [2026-11-03 review](closed-pr-review-2026-11-03.md).

## Scope and method

- **Changes reviewed.** Open pull request #118 and three submitted patches: verification gates (signer policies, dependency reconciliation, A2A v1, Codex TOML, ShadowScan diagnostics), A2A hardening (keyed source binding) and integrity export (`verify-export`, descriptor self-consistency).
- **Two independent reviews per change.** One assumed an attacker controls the scanned repository, a supplied BOM or export, or a live endpoint. The other checked correctness, specification conformance, documentation and tests.
- **Execution-based verification.** Every finding rated medium or higher was re-run by a separate reviewer instructed to refute it. Fixes were written test-first and reviewed adversarially again, including mutation checks that each new test fails when its fix is reverted. Every minor review note and every residual risk a fix reported was then triaged by reproducing it on the final tree, and fixed, documented or dismissed with evidence.
- **Ground truth.** Pathname swaps were reproduced on real overlayfs mounts. Keras findings used real Keras 3.11.2 and 3.15.1 artifacts. GitHub Actions command parsing was checked against `actions/runner` (`ActionCommand.TryParse` finds `##[` anywhere in a line; `TryParseV2` requires `::` at the start). Codex behavior was checked against the `openai/codex` sources and A2A behavior against the A2A 0.3 and v1 specifications.
- **Checks per branch, on the tree merged with current `main`.** Ruff, format, strict mypy over `src` and `scripts`, workflow and hygiene checks, the full suite with coverage floors in an environment whose editable install is the tree under test, security regression contracts, the security benchmark, build and `twine check`, and built-wheel acceptance. The suite also ran on Python 3.11 and 3.13.

A shared environment whose editable install pointed at another checkout made `python -I` subprocesses test the wrong tree. `tests/conftest.py` now refuses that configuration, and it removes an exported `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` so an operator key in the shell cannot change test results.

## Submitted patches

All three were integrated on top of #118 and their review findings fixed. Notable outcomes:

- Signer policies: a project policy can no longer weaken an explicit signer policy, and the signer-policy and dependency-reconciliation entries are marked breaking. A supplied component links to local subjects only the way `verify-live --record` links a served tool, and a supplied `verified` completeness claim fails reconciliation.
- Codex project configuration: every `.codex/config.toml` layer is merged table by table, as Codex does. Permission profiles, `[sandbox_workspace_write]`, writable roots, hooks and approval settings are collected. Full access by any route is a high risk, a profile extending `:danger-full-access` is a collection failure because Codex refuses it, and Codex's trusted-project default of workspace writes counts toward the unprompted-writes finding. Hostile layers are bounded by TOML limits and work budgets.
- A2A: legacy and v1 interfaces are checked for TLS by protocol binding and URL scheme; spec-form gRPC `host:port` interfaces are accepted. Skill-level requirements are recorded and bound but never relax the card-level requirement, which applies to every request (A2A 0.3, section 4.4). Every client URL alias is checked.
- Binding keys must be random material: at least 64 hexadecimal characters, stretched with PBKDF2 before use. An invalid key is reported once per collector; A2A declarations, MCP servers and hooks stay in the inventory unbound.
- `verify-export` compares a received export with the projection of its embedded inventory before schema validation, rejects contradicting CycloneDX dependency rows, bounds the received document and the embedded inventory, and checks uniqueness in linear time.
