# Changelog

Notable changes to Nexus SymBiote, newest release first. Within a release, security changes come first, and changes that need action from users are marked **Breaking**.

## Unreleased

### Security

- **Breaking:** scans now report partial coverage when they encounter selected uncollected instruction, skill, IDE settings or MCP source and configuration surfaces. The default gate can therefore fail for projects that previously passed. Use `--report-only` to inspect the partial inventory and review the identified surfaces separately.
- Operator signature policies can require a signed ShadowScan discovery context binding the report digest to the expected repository, revision, collection scope, producer version and maximum age. Signed producer claims do not prove collection accuracy or prevent replay within the allowed age.
- Bound TypeScript AST depth and per-file analysis time and replace the JavaScript comment hint's quadratic pattern. Use an external timeout and resource limits for the whole scan.

### Assurance

- Document standard export semantics and information loss and exercise partial-coverage exports through independent SDK consumers.
- Add an offline evaluator and protocol for externally selected and adjudicated holdout corpora. No independent field accuracy result is claimed.

## [0.1.0] - 2026-11-07

First alpha of the AgentBOM toolkit under the Hunzee-VC organization. Its known detection gaps, including Claude Code settings beyond the permission mode and blanket grants, skill scripts and subagents, are listed under [known limitations](SECURITY.md#known-limitations-in-010); `diff --fail-on-alert` cannot alert on them.

### Security

- **Breaking:** read `.nexus-symbiote.yaml` only from the project being scanned or named with `--project`. Policy discovery walked every parent directory up to the filesystem root, so a policy file outside the checkout, in a shared workspace parent or in `/tmp`, could skip `validate` checks, hide paths from `scan` and disable the severity gate. `risk` and `validate` also no longer take a policy from the directory an inventory file sits in, which could be `/tmp` or a shared folder: without `--project` they use the built-in policy and name any `.nexus-symbiote.yaml` they did not apply. A policy kept above several scanned subprojects must be copied into each project root, and a gate that relied on a project policy must pass `--project`, which for `risk` also reconciles the inventory against that project. The shipped `nexus-symbiote-risk` pre-commit hook now passes `--project .`, so it applies the repository's policy as the `nexus-symbiote-scan` hook does.
- Reject runtime contract predicates that are not in canonical form. A snapshot signed by a generic DSSE tool with the same contract encoded differently (for example `+00:00` timestamps or omitted default fields) verified under a subject digest that differed from the gateway's revocation and approval identity, so revoking that subject digest was silently ineffective. `runtime verify` now prints the canonical `digest`. `sign_contract` refuses a contract that does not validate or is not in canonical form, so the signer's own digest of a contract is always the digest its envelope binds, and revocation entries must be canonical `sha256:` digests (or 64-digit key IDs for signers): a bare-hex or uppercase entry was compared verbatim and silently ignored, and is now rejected. A timestamp that falls outside the representable range once converted to UTC is now a validation error instead of an uncaught `OverflowError`.
- Cover the C socket type in the offline guard. `_socket.socket` (also `socket.SocketType`) is immutable, so its `connect`, `connect_ex`, `sendto` and `sendmsg` were not replaced and a direct caller could open a connection while a command ran offline; a host-name address was even resolved, sending a DNS query, before any guarded call ran. A CPython audit hook now refuses, for the duration of an offline command, creating any socket other than a Unix-domain socket, the connect and send events, name resolution and process creation, and the guard also replaces the `fork_exec` reference that `subprocess` captures at import. urllib3's import-time IPv6 probe runs before the guard starts, so Sigstore's offline verifier keeps working. A socket created before the command started is not covered: it can still use an existing connection, because `listen`, `accept`, `send` and `recv` raise no audit event, and resolve a host name through `bind`, `connect` or `sendto`.
- Make a checkout-supplied policy relaxation visible. `validate` prints the governing policy source, `risk` records `policy_source` and `policy_weakened` in JSON output, and in human-readable output both print a warning on stderr when a project policy switches off a check, lowers the severity gate, raises the threshold, ignores categories, selects report-only collection or a scanner subset. The warning, and the error for an invalid policy file, neutralize line breaks, terminal controls and invisible format characters from the checkout, so it cannot hide them or forge CI commands. Gate semantics are unchanged; `--no-project-policy` still ignores the file.
- Scope consumed approval nonces by tenant in the gateway state store. One store-global table let a valid approval in one tenant deny a later approval that reused the same nonce string in another tenant; nonces consumed before the change stay consumed for every tenant. Approvers must draw nonces from a cryptographically secure generator with at least 128 bits.
- Name fields only in library-path `AuthorizationError` text for contract validation failures, as the `runtime` commands already did; issuer-authored values no longer appear in the message.
- Compare keyed source-binding tags in constant time during project reconciliation.
- Stop `vex` and `advisories` from printing inventory text in their error messages. They reported validation errors verbatim, so a crafted inventory could print forged lines, GitHub Actions workflow commands (`::error`, `::add-mask::`) or terminal escape sequences on stderr. They now report a fixed message, as every other command that reads an inventory does, and neutralize any later error.
- Parse scanned Python sources without compiler warnings. An invalid escape sequence made CPython print a `SyntaxWarning` that quoted a raw byte of the scanned file, including terminal control bytes.
- Bind every confined read, stream and hash, model inspection, and signed-artifact hashing to both the open descriptor and the pathname. The descriptor's device, inode, link count, size and timestamps must not change, and when the read ends the pathname must still resolve to that device and inode. Size and timestamps alone missed a rename-over within one coarse timestamp tick. The link count alone misses one on overlayfs when the file sits in a lower layer, because the replaced inode is never unlinked: on such a mount a model swapped mid-scan was reported `safe` with a weight hash. Both cases, and an A→B→A swap during the read, now fail closed with safety `unknown`, hashes withheld and a recorded failure.
- Refuse IPv4-compatible (`::/96`) and SIIT-translated (`::ffff:0:0:0/96`) IPv6 destinations in live HTTPS discovery and advisory lookups. The public-address check rated them public even when they embedded loopback, link-local metadata or private IPv4 addresses, such as `::7f00:1` or `::a9fe:a9fe`.
- Neutralize line breaks, including U+2028 and U+2029, in inventory-derived text printed by the CLI. The earlier fix for terminal controls left the newline out, so a file or component name containing one could forge whole output lines, such as a passing status, and in a CI step print lines that GitHub Actions runs as workflow commands (`::error`, `::add-mask::`). `validate` printed such a file name from a scanned repository on 23 lines. Every Unicode format character (category Cf), such as U+061C and the tag characters, is neutralized too, and so is checkout or inventory text quoted in policy, graph and blast-radius errors.
- Inventory PyTorch Lightning `.ckpt`, PaddlePaddle `.pdparams`, Keras `.h5`, `.hdf5` and `.keras`, and TensorFlow `saved_model.pb` model files. They were not discovered at all, so a malicious checkpoint produced no component and no finding while the model collector reported complete coverage. The two pickle-based formats are rated code-executing; the others are reported unknown. Found in an unmerged remediation branch from 2026-11-01 and reproduced on `main`.
- Raise dependency minimums past known advisories: cryptography 50, sigstore 4.4 with tuf 7, and pytest 9.0.3 for development. Sigstore 3.x is no longer supported.
- Lock dependency versions without known advisories (cryptography 50.0.2, sigstore 4.5.1, tuf 7.0.1, pytest 9.2.0) so the required OSV audit of the locked environment passes.
- Keep unused jsonschema format checkers out of the runtime validation worker. With the cyclonedx or all extras installed, their import cost exceeded the worker's CPU limit and every runtime authorization failed closed.
- Require TLS 1.2 or later explicitly in the pinned HTTPS transport, and create `runtime keygen` public keys with mode 0600 like private keys.
- Bind static MCP server structure and reconcile configured tool fingerprints against fresh source evidence; with `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY`, bind configuration values by HMAC so exports never carry a digest that secrets could be guessed from. Require recollection of legacy snapshots without the binding.
- Record A2A security declarations and bind A2A values. Before, a card's endpoint was recorded only as its origin and its required scopes not at all, so moving the endpoint to another path on the same host or widening a required OAuth scope passed `diff --fail-on-alert`, and an empty `security: [{}]` alternative, which permits anonymous access, counted as requiring authentication.
  - A2A 1.0 cards are read as well as 0.3 cards: `supportedInterfaces`, whose first entry is the endpoint when the card has no `url`, `securityRequirements`, and `securitySchemes` named by member such as `oauth2SecurityScheme`, under JSON or proto field names.
  - The scopes that the `security` or `securityRequirements` lists of a card and of its skills name for OAuth and OpenID Connect schemes, with scheme types matched case-insensitively, go into `capabilities.oauth_scopes`. Scope URIs such as `https://www.googleapis.com/auth/drive.readonly` are kept in full and credential-shaped values are withheld, so widening a scope raises a high drift alert without a key. Requirement values of other or undeclared schemes are not exported but enter the structure digest, so changing one raises a medium alert without a key.
  - Scheme types and the origins of security scheme URLs (such as `tokenUrl`), `supportedInterfaces` and `additionalInterfaces` go into properties. A network-path URL, or a bare `host:port` address with a dotted, `localhost` or bracketed-IP host, is exported as `//host:port` and other scheme-less URLs as `[redacted]`, so moving a token endpoint or interface to a host the card did not already use for such a URL raises a medium alert.
  - Structure digests (`nexus-symbiote/a2a-card-structure/v2`, `nexus-symbiote/a2a-client-structure/v1`) cover top-level field names, counts, URL shapes and the requirement alternatives of the card and of each skill. With `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` set, an HMAC over the whole card or client entry (`nexus-symbiote/a2a-card-values/v1`, `nexus-symbiote/a2a-client-values/v1`) detects same-host path, query, tenant and token URL changes. Without the key, records with unbound values carry a low `completeness` risk, and a URL whose origin cannot be exported counts as unbound.
  - `authentication_required` is false, with a medium finding, when a card declares no requirement, an empty requirement list, an empty alternative (which permits anonymous access) or an alternative naming an undeclared or untyped scheme, when a legacy `authentication` object lists no non-empty scheme name, or when a skill declares an empty alternative or one naming an undeclared or untyped scheme; every form the card declares must pass, and skill requirements never make it true. The first A2A 1.0 interface must use HTTPS, like the card's `url`. An A2A URL whose host contains a backslash is exported as `[redacted]`.

- Add a `signature-policy` input to the GitHub Action. Before, with the default `validate: 'true'`, any repository that contained a model failed validation, because no input could supply a signer policy. The Action's runtime lock now includes the `sigstore` extra, whose hashes match `requirements-ci.lock`, and its scans use an empty private Sigstore cache, so a trusted root left in the runner's home cannot decide verification. With a policy and no importable `sigstore`, the Action stops before collection.
- Record what the `registry` collector does not follow in a requirements file as a coverage gap. Includes, constraints files, editable installs and requirements without a package name were skipped, so a package pip installed through them was missing while the collector reported complete coverage and `validate` and `risk` passed.
  - Option lines are now read as pip 26.3 reads them: several options on one line, a value attached or in the next word, an unambiguous prefix of a long name, and `--` taken as an option's value.
  - An include (`-r`) or constraints file (`-c`) whose target is not a root `requirements*.txt` file, or an editable install (`-e`, also after a requirement) that is not the project itself, records `<file>: requirements include not followed`, `constraints file not followed` or `editable install not followed`.
  - A requirement that pip installs from a URL, VCS reference, archive or local path instead of by a package name, with or without `--hash` options or an environment marker, records `<file>: URL, VCS or path requirement not followed`; the project itself (`.`, `./`, `.[extras]` or `file:.`) is exempt. A `name @ URL` requirement is recorded under its name; because pip first reads the whole line as a relative path, a line whose path leaves the project root or starts with an entry of it, such as a directory named `openai @ https:`, also records the same gap.
  - On an option line, an option pip 26.3 does not know records `option line not parsed`, because another pip may give it a value, and a `${NAME}` variable in a requirement's name or in an option line's option place records `environment variable not resolved`; options after a requirement on the same line, other than `-e`, are not checked. A file that declares an encoding other than UTF-8 is a collection failure (`<file>: declared encoding other than UTF-8: not read`). No gap names its target, which can carry a credential.
- Read `Dockerfile` and `Dockerfile.agent` `FROM` instructions as BuildKit's parser does in the `registry` collector. The first word after an upper-case `FROM` was taken as the image, so an image in a lower-case instruction, behind a `--platform` flag or on a continued line was dropped without a gap, and a `FROM` line inside a heredoc body was collected.
  - The instruction word is now matched in any case, `--flag` words are skipped, continued lines are joined with comment and empty lines dropped, and the joined instruction is trimmed of white space at both ends as BuildKit trims it, so a line holding only a backslash does not hide an indented `FROM` after it, and a trailing no-break space is not part of the tag. Heredoc bodies of `RUN`, `COPY` and `ADD`, also after `ONBUILD`, are skipped, and a `FROM` naming an earlier build stage is not an image.
  - These are coverage gaps: a `FROM` image with an ARG substitution (`FROM image substitution not resolved`) or with quotes or escapes (`FROM image quoting not resolved`); a `FROM` without an image or with a quoted or escaped flag (`FROM instruction not parsed`); a heredoc that cannot be parsed or is not terminated (`heredoc not parsed`); and an escape parser directive other than a backslash (`escape parser directive not followed`).
- Translate `[tool.poetry]` dependencies in the `registry` collector, including the `dev-dependencies` and `group.*.dependencies` tables, to PEP 508 instead of joining name and version: `torch = "2.3.1"` was recorded as the package `torch2-3-1`. A bare version is an exact pin, caret, tilde and wildcard constraints become ranges, and extras, markers and platform are kept. A git, path or URL dependency, a dependency with a `source` other than PyPI, and a condition that does not translate (a `||` union or a `python` restriction) are recorded by name with a coverage gap. An invalid dependency is a collection failure.

### Fixed

- Read every `requirements*.txt` in the project root in the `registry` collector, as documented, matching names without regard to case. It read only `requirements.txt`, `requirements-dev.txt` and `requirements-ml.txt` and still reported complete coverage. It now joins continued lines as pip does, with nothing in between, and ignores per-requirement options such as `--hash`, so hash-locked files no longer fail, and it strips a UTF-8 byte order mark, so the first requirement of such a file is no longer skipped without a finding. A newly read entry that is not a readable regular file, is not UTF-8, or has a line naming an AI package that is not a valid requirement is reported as a collection failure, as such a `requirements.txt` already was, and a file whose name holds undecodable bytes or a control or format character is reported as a failure and not read. All root requirements files together are read up to 4 MiB; beyond that the rest are reported as a collection failure and not read, so scan time stays bounded. A package declared more than once in requirements files, in one file or several, becomes one component instead of a conflicting duplicate that failed the scan (identical lines in one file were already merged), and a `pyproject.toml` declaration of a package already declared, previously dropped, is recorded on that component too. A finding is raised only when two declarations under the same markers conflict: two exact pins neither of which admits the other (`==2.3.0` admits the local build `2.3.0+cpu` that a lock file records, so those do not conflict), an exact pin outside another declaration's range, or a direct URL reference whose origin another declaration does not share. A range and a pin that satisfies it, as pip-tools, uv and lock files write them, do not conflict. Ranges are not compared with each other; declarations under different markers, such as the platform splits `uv export` writes, or in different `[project.optional-dependencies]` groups, such as uv's `cpu` and `cu121` extras, are not compared; the extras a requirement names, such as `openai[datalib]`, are not compared; and a declaration that cannot be parsed is reported as a collection failure instead. The comparison takes time linear in the size of the files read; a declaration with a version longer than 128 characters is recorded but not compared. Each declaration from a requirements file or the `[project]` table is recorded, redacted, so a change to its version, marker, extras or URL scheme, host or port reaches `diff`; `[tool.poetry]` dependencies are covered by a separate entry. A direct URL or VCS reference containing `//` keeps only its scheme, host and port, taken from the whole parsed URL so that a quote inside it cannot leave the rest behind, and a line that cannot be parsed is recorded only up to the word that holds its first `//`, because a path or query can carry credentials; a change within the same origin therefore does not reach `diff`. Such a URL without a host is replaced entirely, and a reference written without `//`, such as `file:/path`, or a relative path is recorded as written. Options are split from a requirement on spaces only, as pip does, so a tab or another space character stays inside the requirement. Includes, constraints files, editable installs and URL, VCS and path requirements are covered by a separate entry; the targets of references are still not fetched.
- End a command with a plain error, not a Python traceback, when its output path cannot be written safely: a symbolic link on the way, a missing directory, or a directory as the target. Other failures, such as a permission error or a full disk, are reported by the system's message, without the path. This applies to the `-o`/`--output` file of every command and to `init --path`; `runtime keygen` still ends such a failure with a traceback. `init --path` follows the same rule instead of writing through a symlinked directory, `vex` and `advisories` also refuse a second name for their input, such as a hard link, and no command replaces a device, FIFO or socket named as its output. `..` in an output path now steps to the real parent directory, as the operating system resolves it, instead of being refused.
- Report a missing `sigstore` extra in `verify-artifact` and `verify-discovery` as such, not as a failed signature.
- Run the README's verified-install version check as the last step of its subshell, using the program in `.venv`. After a failed step it printed the version of an earlier install on `PATH` and exited 0. A test runs the published block under bash with stub tools and requires it to stop, install nothing and exit non-zero after each failed step.
- Report a collector that produced a conflicting duplicate component or a dangling dependency edge as failed in `collectors_completed`, not only in `scanner_status`. A clean `ScanResult` no longer lets an orchestration-level failure be recorded as completed collection, or raise the inventory's completeness assurance to `observed` on its own. Gates were already failing through `scan_failures`; the emitted coverage record was the inaccurate part.
- Run the GitHub Action on runners whose temporary directory path contains a symlink, as on macOS. The CLI's no-follow file handling refused the Action's scratch files.
