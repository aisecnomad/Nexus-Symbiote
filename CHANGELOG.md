# Changelog

Notable changes to Nexus SymBiote, newest release first. Within a release, security changes come first, and changes that need action from users are marked **Breaking**.

## [Unreleased]

### Security

- **Breaking:** `hook_commands` rates more fetch-and-run hook commands critical. A shell, `eval` or process substitution that runs a download or decode was read only in the first segment of each pipeline, so `true | bash -c "$(base64 -d <<< ...)"` was medium and `true | bash -c "$(curl ...)"`, `true | eval "$(curl ...)"` and `true | sh <(curl ...)` were high; every segment is read now. PowerShell's name was matched before the shell removed quotes and escapes, so `p'w'sh -enc ...`, `p\wsh`, `pw''sh` and `po'wer'shell -EncodedCommand ...` were medium; the decoded name is matched too, and an encoded-command flag after a command word the shell computes, such as `p=pwsh; $p -enc ...` or `/usr/bin/pw?h -enc ...`, fails closed as critical, as do `-e` and `-ec` there when a base64 argument follows them; `$SED -En`, `$GREP -e` and `$SHELL -ec 'true'` stay medium. A download saved under an attached `-o` in a flag cluster (`curl -sLo/tmp/x.sh URL`), under the URL's name by `curl -O`, `-LO` or `--remote-name`, or by `wget URL` without `-O`, and then run was high; it is critical, as `curl -o /tmp/x.sh URL; bash /tmp/x.sh` is. A file saved under its URL's name counts only as the script or program, so `wget URL/data.csv && sh scripts/load.sh data.csv` stays high. Leading words that bash reads as assignments (`X=1`, `X+=1`, `X=$(id -u)`) are skipped, so `curl URL | X=1 bash` is critical, where it was high; a word that only looks like one, such as `1=/bin/sh`, `a.b=/bin/sh` or `"X"=/bin/sh`, is the command. A second downloader name in the same command, as in `wget -U curl -O /tmp/y.sh URL; sh /tmp/y.sh`, was read as a new command and switched which tool's output flags were read, which made that form high; it is critical. A curl flag cluster with `o` before its end is read as curl reads it, so `curl -sozo x.sh URL && bash x.sh` and `curl -fo/tmp/foo URL && sh /tmp/x.sh`, which do not run what they download, fall from critical to high. (P1-H4, P1-H5, P1-M16)
- **Breaking:** `permission_scope` reports more unscoped Claude Code allow rules. A `Bash` rule naming a shell or interpreter by a Windows path (`Bash(C:\Python312\python.exe -c *)`, `Bash(C:\Windows\System32\cmd.exe /c *)`), with a `.exe`, `.cmd` or `.bat` suffix (`Bash(python.exe -c *)`) or after `VAR=val` words (`Bash(FOO=1 bash -c *)`) was read as scoped, as was `WebFetch(domain:**)` or `WebFetch(domain:*.*)`. The program is read without its directory, suffix and leading assignments, and any domain made only of `*` and `.` is unscoped. (P1-M15)
- **Breaking:** `.claude/settings.local.json` no longer suppresses the starting-mode, MCP auto-approval and credential-helper findings that the committed `.claude/settings.json` raises. The files were merged and the `bypassPermissions` `permission_scope`, `mcp_auto_approval` and `credential_helper` findings read the merged value, so a local file setting `defaultMode: "default"`, `enableAllProjectMcpServers: false` or `apiKeyHelper: null` removed them, although every clone without that uncommitted file runs with the committed value. Each finding is now raised from the file that declares it and, when a later file overrides it, names that file; `permission_mode` and `settings_declarations` still record the effective merged value. The local file still suppresses `oversight_gap`, `plugin_sources` and `additional_directories`, which read the merged value. (P1-M14)
- `audit-control-plane` no longer writes a credential found in a checkout's names, paths or permission rules to its JSON summary (`--json-output`, `-o`). A token in a hook target path or an MCP server name reached `hook_targets[].target_path`, `steering_surfaces[].server_name`, `security_flags[].component_name` and `relationships[].target_ref` verbatim, while text mode redacted it. Every output is now rendered from one copy redacted the way inventories are, and text-mode findings and diff alerts are printed from that copy too.
- **Breaking:** the `model` collector reads a ZIP archive's directory the way `zipfile` and the C++ reader `torch.load` uses (miniz) find it in more layouts. A ZIP64 locator or record inside the first local header or its name, in an archive smaller than the bytes the collector retains, was never seen, because those bytes were read before the directory search and not kept: a decoy end record naming an empty directory then hid the member both readers list, so a 374-byte `.npz` holding an object-dtype array was left out of the inventory with no coverage gap, and a `.pt` holding `archive/data.pkl` fell from critical to high. A ZIP64 record that the locator places after itself, which miniz reads and `zipfile` with the CVE-2025-8291 fix refuses, was dropped, so the decoy directory the classic record names was the only one listed. Both now list the member, `unsafe-code-execution`. A directory that cannot be decided no longer hides one that can: a ZIP64 locator whose offset lies before the bytes the collector retains, or a directory past the bound, made the whole archive `unknown` even when the classic directory listed a pickle or object array, so a 20-byte entry comment shaped like a locator storing offset 0 let a critical `.npz`, `.keras` or `.onnx` pass the default gate as high. Every reading is now rated, and the archive is `unknown` only when none of them lists such a member. An end record that only miniz finds is now read: one behind a truncated end-record signature at the end of the file, or more than 65,557 bytes from the end, both of which `zipfile` refuses, made the archive a directory not read, so a `weights.dat` holding `archive/data.pkl` passed the gate. A classic record with saturated counts or offsets was dropped whenever any ZIP64 record was found, although miniz reads it when the locator's offset holds no record, and `zipfile` without that fix when the record before the locator is missing: it is now dropped only when a record lies where every reader looks, so a 65,535-entry directory that miniz lists behind a decoy record is not decided (`ZIP archive whose directory is malformed or over the inspection limit`). A directory that starts at its stored offset and runs past its end record, which no writer produces and miniz still reads, is now not decided either, where only `zipfile`'s decoy reading was kept. Such an archive is `unknown`, a high finding and a coverage gap, or `unsafe-code-execution` under a pickle-family name such as `model.pt`. An archive cut out of a larger file, whose stored offsets start no directory entry, keeps the rating `zipfile`'s reading gives it, and an archive followed by another, whose last end record falls inside the first local header's name, is rated by the directory that record names, as `zipfile` and miniz list it, where it was not decided. Archives written by `zipfile`, `numpy.savez` and `torch.save` are rated as before ([known limitations](docs/known-limitations.md)).
- **Breaking:** every command exits with status 1 and `unsupported platform` on a host without POSIX `O_NOFOLLOW`, `O_DIRECTORY` and descriptor-relative `open`, such as Windows, before it reads anything; `--help` and `--version` still answer. Confined collection already failed there, but other reads, such as loading a policy, fell back to opens that follow links. Windows is unsupported by decision ([platforms](SECURITY.md#platforms)); run the container image there.
- **Breaking:** `StateStore.record` deletes used approval nonces from the store clock, not from the expiry just presented, and refuses an expiry more than five minutes ahead of that clock. The deletion used `not_after` minus seven days, so a nonce whose expiry was eight days out removed every other tenant's nonce that expired within the next day, including one still inside the retention window; a direct caller of `record` could present that expiry. `ReferenceGateway` already refuses an approval longer than five minutes, so that path could not. Pass `now` to choose the clock in a test. A call never deletes the row it records, so a nonce whose expiry is more than seven days behind the clock is still refused when it is presented again. A row with no expiry is still kept.
- `audit-control-plane` no longer copies a parser or read exception into a coverage gap. PyYAML and the JSON parser quote the line that failed, so a workflow, `agent.yaml`, claims file or MCP config that does not parse put that line, secrets included, into the gap text and then into the report; the gap now says only `invalid YAML`, `invalid JSON`, `invalid inline mcp_config` or `read refused`. The YAML token scan uses `SafeLoader`. A document past 20,000 tokens is still refused, and the gap for it says `invalid YAML` rather than the token count.
- **Breaking:** `verify-live` exits with a usage error when a host credential is set in the environment (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AZURE_CLIENT_SECRET`, `GOOGLE_APPLICATION_CREDENTIALS`, `GH_TOKEN`, `GITHUB_TOKEN`, `NPM_TOKEN`, `NODE_AUTH_TOKEN`, `PYPI_TOKEN`, `DOCKER_PASSWORD`, `KUBECONFIG`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) unless `--allow-host-credentials` is passed. The launcher is started with a cleared environment, but the pin is not a sandbox: `--no-isolation`, a PID-namespace escape and a parent that dies before cleanup still run code as the invoking user. The error names the variables, never their values. `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` is not one of them. An empty value does not count.
- **Breaking:** the `model` collector no longer lets a decoy hide a ZIP64 directory stored before the 1 MiB tail it reads. A ZIP64 locator whose offset pointed before that tail was dropped, and the decoy ZIP64 record right before the locator was read instead. `zipfile` from Python 3.13 reads the record at the locator's offset first, taking the bytes between as extensible data, so a 1.3 MB `.npz` with an object-dtype array was left out of the inventory, and the same archive named `.pt` fell from critical to high, with no gap either way. Such an archive's directory is now unread (`ZIP archive whose directory is malformed or over the inspection limit`): a pickle-family name keeps the critical code-execution rating, and any other model file is inventoried as `unknown`. GGUF metadata arrays nested more than two deep are now an inspection limit, not unreadable metadata, so the chat templates they hide are a coverage gap in `surfaces_excluded`. The chat-template heuristic also matches Python-mangled private names such as `self._TemplateReference__context` or `self['_TemplateReference__context']`, and underscore strings repeated with `*`, as in `('_'*2) ~ 'class' ~ ('_'*2)`, both of which it missed before.

- **Breaking:** hidden characters in the text of a tool definition are rated as they are in an instruction file. The `mcp` collector reads every string and key of each entry in a server's `tools` array, except the tool's name, before redaction, and raises `invisible_characters` (high), `bidi_override` and `tag_characters` (critical), `directional_marks` (medium) and `line_separators` (low) on the tool. A description such as `Look up a ticket.` followed by a zero-width space, Unicode tag characters and a right-to-left override scanned with the same findings as the plain description, so text a host shows the model and a reviewer cannot see passed every gate; only `diff` against a reviewed baseline reported the changed definition. A scan of such a file now fails the built-in gate on the critical findings. Emoji sequences, accented text and right-to-left prose without directional marks raise nothing. Descriptors recorded by `discover-mcp --record` and `verify-live --record`, and tools declared in server source, whose descriptions are not collected, are not read yet.
- **Breaking:** the `model` collector records `serialization_format` and `model_type` for a `.gguf` or `.safetensors` file only when the file's header is that format's: the four bytes `GGUF` before content that is not rated `unsafe-code-execution`, or a SafeTensors header that validates. A 47-byte text file named `not_a_model.gguf` was recorded as a `foundation` model in `llama.cpp` format, and exported to CycloneDX with `modelType` and `serializationFormat`, on its suffix alone, although the GGUF reader had already failed on it; arbitrary bytes, a pickle or an unreadable file under either suffix was recorded the same way. Such a file is still a component, with the `unknown` or `unsafe-code-execution` rating and the findings it had, but without those two fields: `properties.named_format` holds the format its name claims, and for a `.gguf` file `properties.format_inspection` says `Named as GGUF, but the content does not start with the GGUF magic; the format was not established`, or `Named as GGUF, but too short to hold the GGUF magic; the format was not established` under four bytes, where it said `No bounded structural validator for this format/loader`. `risk` raises `invalid_safetensors`, which fails the gate at any score, from `named_format` as it does from `serialization_format`, and the collector also stores that finding on the record, because a release up to 0.2.0 derives it from `serialization_format` alone and would otherwise pass the gate on an inventory this release wrote. So a file named as SafeTensors that does not validate fails as before, in this release and in an earlier one that reads the new inventory. A valid file of either format, a `.gguf` file with the magic whose version or metadata cannot be read, and files under the suffixes that have no header check are recorded as before. For each file whose header is not its format's, an inventory collected earlier differs from a new collection: `diff` reports `serialization_format changed.`, `model_type changed.` and the changed properties as one alert, and `validate --project` reports the component as `Missing or mismatched local component`, so collect and approve the baseline again. The alert is medium, except for a file named as SafeTensors that does not validate and is not a pickle, a ZIP holding a pickle or a NumPy object array, where it is high and begins `Risk findings added: 1 high (invalid_safetensors).`, because the stored finding is new on the record ([model integrity](docs/model-integrity.md#format-and-model-type), [migration](docs/security-defaults-migration.md)).
- Added `diff-instructions BASE_TREE HEAD_TREE` (`R1.1-10`) to compare instruction files through confined, no-symlink reads and report security-relevant CommonMark and front-matter changes (`tool_grant_changed`, `import_added`, `url_or_path_added`, `hidden_markup_added`, `scope_widened`), withholding text unless `--show-text` is passed and redacting/neutralizing every displayed line.
- Operator policy verification rejects trust keys inside an explicit scan target or its enclosing checkout. Step summaries refuse hard-linked output files.
- **Breaking:** a pickle-family file name (`.pkl`, `.pickle`, `.pck`, `.dill`, `.pt`, `.pth`, `.bin`, `.joblib`, `.ckpt`, `.pdparams`, also inside `.tar`, `.gz` and the other wrapper suffixes) is rated by its inspected content, not by the name alone. It stays critical, with evidence naming what was recognized, when its first 64 KiB are a recognized pickle opcode stream, a NumPy object-dtype array or a ZIP archive with a pickle member, as a torch archive is, or such an array, and critical with `Potential code-executing loader format (...)` around the bounded verdict when they are a pickle opcode stream, a ZIP archive or a NumPy array that the inspection bounds cut short or left unread. A compressed or archived stream, named with a wrapper suffix or starting with gzip, zlib, bzip2, xz, Zstandard, LZ4 frame or joblib `ZF` magic, an LZMA-alone header after joblib's `5d 00`, the ustar magic, or a tar header that `tarfile` reads without it, stays critical with `Potential code-executing loader format (compressed or archived stream; decompressed content not inspected)`, as pandas, joblib and `torch.load` unwrap it before unpickling; so is a raw array whose first bytes form such a header, such as 32-bit integers that start at 93. A file that starts with the GGUF magic, whatever follows, stays critical under such a name with `Potential code-executing loader format (GGUF content under a pickle-family name; its chat templates are not inspected under this name)`, as llama.cpp opens a model by its magic, not its name, and the chat-template check runs only under a `.gguf` name. A readable file that shows none of that, such as a zero-filled `data/raw/embeddings.bin`, is `unknown` with the evidence `Named pickle-family format; no pickle evidence in the inspected prefix` (`empty file` for a zero-length one) and the high `serialization_format_unknown` finding, which the default gate does not fail on by severity alone; it was critical and failed the gate. A ZIP archive whose directory was read whole and lists no pickle-family member or object-dtype array keeps its own `unknown` verdict (`ZIP archive whose directory lists no pickle member; no bounded structural validator for this format/loader`) with the same finding. A pickle-family file that cannot be read keeps the critical rating. First slice of opcode-level model analysis (ROADMAP X4). After upgrading, `diff` against an inventory collected before it reports every pickle-family file once, `properties.format_inspection changed` at medium, and at high where the rating moved to `unknown`, and `validate --project` against such an inventory reports each as a missing or mismatched local component; recollect and review the baseline once (`docs/fingerprint-migration.md`).
- Added `--operator-policy` (requiring `--operator-policy-attestation` and `--operator-policy-key` by default, with `--allow-unsigned-operator-policy` to opt out explicitly and `--operator-policy-max-age-days` defaulting to 90 days) on `scan`, `validate`, and `risk`, plus `attest --purpose policy`: operator policies must live outside the scanned checkout and enclosing repositories, project policies may only monotonically narrow them, and `operator:<digest>` provenance is recorded in native JSON, gate reports, and SARIF.
- Added `diff --expect-upgrade FROM_VERSION` (`0.1.0` or `0.2.0`) to partition documented profile/schema transitions into `tool_upgrade_changes` when `metadata.tool_version` matches, while keeping configuration, source-binding, and hash drift in `security_alerts`.
- Added `--report-format` (`text`, `json`, `markdown`, `junit`) and `--step-summary` (injection-safe Markdown summary append) on `validate`, `risk`, and `diff`, plus `--detailed-exit-codes` (`0` passed, `2` usage, `3` gate/verification failed, `4` collection/input/internal failure) and `--legacy-exit-codes`.
- Added `sk-ant-` Anthropic token redaction to `utils/secrets.py`.
- Added offline advisory matching with SHA-256 provenance, alias-pair deduplication, and CISA/ENISA KEV + EPSS enrichment (`nexus-symbiote advisories --offline-db [--kev ...] [--epss ...]`, `nexus_symbiote.offline_advisories`): pinned PyPI and npm packages match offline OSV bundles with zero network calls, alias pairs (`CVE-*` / `GHSA-*`) collapse into one entry, and KEV-listed advisories elevate severity to `critical` with source attribution. A bundle or catalog that is empty or wrongly shaped is refused, a package whose ecosystem the bundle holds no record for is an error, and the report's provenance counts the records and catalog entries loaded, so none of them can pass as a complete result with no advisories.
- Offline advisory feeds that are stale or undated no longer yield a complete result (`nexus-symbiote advisories --offline-db ... --max-feed-age-days N`, default 30). A years-old OSV bundle, KEV catalog or EPSS file still reported `complete: true` with no advisories, and nothing in the report showed its age. The report's provenance now carries the date each feed states about itself (`db_newest_record` from the records' `modified` or `published`, `date_released` from a KEV catalog's `dateReleased`, `score_date` from the EPSS file), never a file time. A feed older than the limit, without a date, or dated more than a day in the future adds a named error, so `complete` is `false` and the command exits 1; a date that is present but not RFC 3339 refuses the feed. The limit is 1 to 36500 days and cannot be turned off; pass a larger number to accept an old feed deliberately. `match_offline_advisories` takes the reference time as a required `now` argument, and only the CLI reads the clock. **Breaking for #273's unreleased interface:** a KEV or EPSS file that states no date now makes the report incomplete.
- `scan` no longer ends with `internal error (OSError)` on a checkout that holds a collected file whose path is longer than the system limit (1,024 bytes on macOS, 4,096 on Linux). The text-poisoning pass asked whether each source path was a directory with a path-based `stat`, which fails with `ENAMETOOLONG` there and follows symbolic links; it now asks the confined collection, as every read in that pass already did.
- Offline advisory matching (`nexus-symbiote advisories --offline-db`) no longer compares every version of a package with every advisory for it. 200 versions of one package against 20,000 advisories that matched none of them took 13.5 s of CPU and reported a complete result, and the cost grew with the product of the two, so a committed inventory and a crafted bundle could hold a CI job for hours within the existing size limits. Each package's advisories are now indexed once by the versions they match, so a version costs a lookup plus the records that do match it; the same input takes about a second, and the matches and their `undecidable_bounds` are unchanged, as is the error for each version a record that cannot be evaluated would have been evaluated for. What still grows with both inputs, records that match and ranges with thousands of events, is bounded by the new operator limit `advisory-matches` (default 2,000,000, `--limit advisory-matches=N`): past it, matching stops with one error, the report is not complete and the command exits 1.
- Offline advisory directory imports bound all entries before sorting, including files outside the JSON feed.
- Extended CycloneDX 1.7 VEX generation (`nexus-symbiote vex --decisions --project-root --advisories --trace-evidence`, `nexus_symbiote.vex_decisions`): operator-owned VEX decisions outside the checkout record `not_affected`, `exploitable`, `resolved`, and `false_positive` with owner and deterministic expiry (expired decisions revert to `in_triage` with a warning); execution-bound trace evidence yields distinct outcomes for `declared-never-loaded`, `invoked`, and `shadowed` components, and never states `exploitable`: an invoked component's findings stay `in_triage`; advisory reports link into VEX `vulnerabilities`.
- **Breaking:** every collected component's `name`, `description` and `supplier`, and the tool names under an MCP server's `client_settings`, are neutralized once, where collector output is merged into the inventory, and so are the repository agent's and its `agent.yaml` components' fields, the details of every finding and the `surfaces_excluded` and `scan_failures` text. A server named `browser` followed by ESC `[2K` reached the CycloneDX export as `\u001b[2K`, which one unescape in a consumer makes a live terminal sequence again; only printed text went through `safe_line`. A tab, line break, form feed, backspace or delete becomes a space, as does the second `#` of a CI log-command introducer, and other C0 and C1 controls, ESC, bidirectional and other format characters become U+FFFD, in the native, CycloneDX, SPDX, SARIF and VEX outputs; JSON writes none of the replacements in more bytes than the character it replaces, so an inventory that fitted the 16 MiB native limit still does. The SHA-256 of each rewritten field's raw text is recorded under the component's `neutralized_raw_sha256` property, and a component whose name, description, supplier or nested tool names held such a character, other than a tab or line break in a description or supplier, carries one new high `identifier_characters` finding naming each character class, its count and the SHA-256 of the raw value, never the raw text. The same finding reports an MCP server or tool name that mixes scripts within a word (Latin and Cyrillic or Greek lookalikes in one word), or that has, beside Latin text, a Cyrillic, Greek or Armenian word whose every letter reads as a Latin one (`shell_ехес`, `github.сом`), which was not reported at all. Ordinary text is kept and not reported: an `agent.yaml` `purpose:` whose parsed value keeps line breaks (a literal block scalar, or a folded one without the strip indicator `-`), whose line breaks become spaces; an `agent.yaml` `name:` written as a clip block scalar (`name: >` or `name: |`), recorded without the one line break YAML ends it with; a variation selector after an emoji or in a keycap; a zero-width joiner between emoji; a joiner where IDNA's CONTEXTJ rules allow it, after a virama on a letter of its own script (the Indic scripts) or, for U+200C, between letters that join (Persian, Arabic and the other cursive scripts); and a word in one script beside a word in another, such as `GitHub-интеграция` or `MCP сервер`, which is recorded exactly as before. References derived from an A2A card's, A2A client's or RAG source's name percent-encode those characters (`a2a-server:browser%1B[2K`), so no export carries them in a `bom_ref`, dependency, `component_ref`, VEX statement or graph node; MCP references were already digests of the raw name. `trace-diff` compares names by their raw text: a rewritten inventory name matches only a reported name with the recorded SHA-256, so a tool declared as `run<TAB>job` no longer matches a span reporting `run job`, and an emoji or Persian name a span reports exactly matches; both are trimmed of surrounding spaces, tabs and line breaks first, as before, so a tool declared as `<TAB>lookup` still matches a span reporting `lookup`. `export-inventory` refuses an agent name or owner that collection rewrote, as it refused the raw text, and `minimum-elements` counts a value left with only U+FFFD and white space as missing. A tool whose name changed still passes integrity validation: its displayed descriptor digest is bound to the neutralized name. A tool's `description_text`, path-derived values such as a prompt import's `bom_ref`, and live-mode inventories are not neutralized ([known limitations](docs/known-limitations.md#every-collector)). Content digests change only for components whose fields held such characters or whose names mix scripts within a word, once; a component with a line break in its description or supplier is one of them. Suppressions of findings whose detail quotes a rewritten name, and policy entries naming a changed A2A or RAG reference, must be renewed ([fingerprint migration](docs/fingerprint-migration.md#neutralized-identifiers)).
- **Breaking:** a literal credential in an MCP server's `env` value, launch argument, header or endpoint URL query raises a high `credential_exposure` finding on the server. The inventory already redacted such a value, but nothing told the operator that a credential is committed; `transport_security` covers only user information in an endpoint URL. The finding names the positions (`env API_TOKEN`, `argument 4`, `header Authorization`, `endpoint URL query`; `an env key` or `a header` when the name itself is withheld) and the class (a vendor token shape, an authorization scheme credential or a generic secret-like value), never a value, prefix or length. The category is in the [finding catalog](docs/finding-catalog.md#categories) and the [framework crosswalk](docs/framework-crosswalk.md#credential_exposure), where CWE-798 and the OWASP LLM02 entries are new. Only what is precisely a literal counts, although the scrubber still redacts broadly. A vendor token shape counts under any name unless it is a placeholder (`ghp_xxxx...`, `sk-your-openai-api-key-here`, `AKIAIOSFODNN7EXAMPLE`) or a JWT, bare or after `Bearer`, under an `anon`, `anonymous`, `public`, `publishable` or `pk` name (`SUPABASE_ANON_KEY`), which is published by design, while other values under such names count as before (`PK_PASSWORD`); DigitalOcean (`dop_v1_`, `doo_v1_`, `dor_v1_`), Linear (`lin_api_`, `lin_oauth_`), Atlassian (`ATATT3`), age (`AGE-SECRET-KEY-1`) and Discord bot tokens (a first part that starts with M, N or O and holds a digit, then a stamp that is not a lower-case word, so `Acme2024.plugin.RouterImpl`-style class names are not) are new token shapes, which the scrubber now redacts everywhere too; so do a private key block, a PuTTY private key or either in base64, a password in URL user information, a `Password=` or `AccountKey=` pair of a `key=value;` connection string (an ODBC `Pwd={...}` unquoted) or of a libpq `host=db user=app password=...` string, and a scheme word with one credential-like word after it (`Bearer <token>`, but not `Basic calculator tools` or `Bearer realm=...`). Under an `Authorization` or `Proxy-Authorization` header any value of eight or more characters counts unless it is a reference, a placeholder or a word phrase (`Bearer svc:hunter2hunter`, a `Digest` response), and a `Cookie` header is read pair by pair, where a value counts at 16 or more characters, or under a session name (`sid`, `session`, `auth`, `token`), but never in an analytics cookie (`_ga`, `_gid`, `_fbp`). A header value with a line break injects a header line after it (`abc\r\nAuthorization: Bearer ...`), which is read at the position of the header that carries it. 3. Review the new findings and coverage gaps; a gap fails the default gates. 7. Where a CI job exports `SOURCE_DATE_EPOCH`, make it a whole number of seconds or unset it before `scan`, `baseline` and `import-shadowscan`; where an inventory must record when it was collected, set it, because without it none is recorded.

### Security

- **Breaking:** read `.nexus-symbiote.yaml` only from the project being scanned or named with `--project`. Policy discovery walked every parent directory up to the filesystem root, so a policy file outside the checkout, in a shared workspace parent or in `/tmp`, could skip `validate` checks, hide paths from `scan` and disable the severity gate. `risk` and `validate` also no longer take a policy from the directory an inventory file sits in, which could be `/tmp` or a shared folder: without `--project` they use the built-in policy and name any `.nexus-symbiote.yaml` they did not apply. A policy kept above several scanned subprojects must be copied into each project root, and a gate that relied on a project policy must pass `--project`, which for `risk` also reconciles the inventory against that project. The shipped `nexus-symbiote-risk` pre-commit hook now passes `--project .`, so it applies the repository's policy as the `nexus-symbiote-scan` hook does.
- Reject runtime contract predicates that are not in canonical form. A snapshot signed by a generic DSSE tool with the same contract encoded differently (for example `+00:00` timestamps or omitted default fields) verified under a subject digest that differed from the gateway's revocation and approval identity, so revoking that subject digest was silently ineffective. `runtime verify` now prints the canonical `digest`. `sign_contract` refuses a contract that does not validate or is not in canonical form, so the signer's own digest of a contract is always the digest its envelope binds, and revocation entries must be canonical `sha256:` digests (or 64-digit key IDs for signers): a bare-hex or uppercase entry was compared verbatim and silently ignored, and is now rejected. A timestamp that falls outside the representable range once converted to UTC is now a validation error instead of an uncaught `OverflowError`.
- Cover the C socket type in the offline guard. `_socket.socket` (also `socket.SocketType`) is immutable, so its `connect`, `connect_ex`, `sendto` and `sendmsg` were not replaced and a direct caller could open a connection while a command ran offline; a host-name address was even resolved, sending a DNS query, before any guarded call ran. A CPython audit hook now refuses, for the duration of an offline command, creating any socket other than a Unix-domain socket, the connect and send events, name resolution and process creation, and the guard also replaces the `fork_exec` reference that `subprocess` captures at import. urllib3's import-time IPv6 probe runs before the guard starts, so Sigstore's offline verifier keeps working. A socket created before the command started is not covered: it can still use an existing connection, because `listen`, `accept`, `send` and `recv` raise no audit event, and resolve a host name through `bind`, `connect` or `sendto`.
- Make a checkout-supplied policy relaxation visible. `validate` prints the governing policy source, `risk` records `policy_source` and `policy_weakened` in JSON output, and in human-readable output both print a warning on stderr when a project policy switches off a check, lowers the severity gate, raises the threshold, ignores categories, selects report-only collection or a scanner subset. The warning, and the error for an invalid policy file, neutralize line breaks, terminal controls and invisible format characters from the checkout, so it cannot hide them or forge CI commands. Gate semantics are unchanged; `--no-project-policy` still ignores the file.

One store-global table let a valid approval in one tenant deny a later approval that reused the same nonce string in another tenant; nonces consumed before the change stay consumed for every tenant.   - These are coverage gaps: a `FROM` image with an ARG substitution (`FROM image substitution not resolved`) or with quotes or escapes (`FROM image quoting not resolved`); a `FROM` without an image or with a quoted or escaped flag (`FROM instruction not parsed`); a heredoc that cannot be parsed or is not terminated (`heredoc not parsed`); and an escape parser directive other than a backslash (`escape parser directive not followed`).
- Translate `[tool.poetry]` dependencies in the `registry` collector, including the `dev-dependencies` and `group.*.dependencies` tables, to PEP 508 instead of joining name and version: `torch = "2.3.1"` was recorded as the package `torch2-3-1`. A bare version is an exact pin, caret, tilde and wildcard constraints become ranges, and extras, markers and platform are kept. A git, path or URL dependency, a dependency with a `source` other than PyPI, and a condition that does not translate (a `||` union or a `python` restriction) are recorded by name with a coverage gap. An invalid dependency is a collection failure.

### Fixed

- Read every `requirements*.txt` in the project root in the `registry` collector, as documented, matching names without regard to case. It read only `requirements.txt`, `requirements-dev.txt` and `requirements-ml.txt` and still reported complete coverage. It now joins continued lines as pip does, with nothing in between, and ignores per-requirement options such as `--hash`, so hash-locked files no longer fail, and it strips a UTF-8 byte order mark, so the first requirement of such a file is no longer skipped without a finding. A newly read entry that is not a readable regular file, is not UTF-8, or has a line naming an AI package that is not a valid requirement is reported as a collection failure, as such a `requirements.txt` already was, and a file whose name holds undecodable bytes or a control or format character is reported as a failure and not read. All root requirements files together are read up to 4 MiB; beyond that the rest are reported as a collection failure and not read, so scan time stays bounded. A package declared more than once in requirements files, in one file or several, becomes one component instead of a conflicting duplicate that failed the scan (identical lines in one file were already merged), and a `pyproject.toml` declaration of a package already declared, previously dropped, is recorded on that component too. A finding is raised only when two declarations under the same markers conflict: two exact pins neither of which admits the other (`==2.3.0` admits the local build `2.3.0+cpu` that a lock file records, so those do not conflict), an exact pin outside another declaration's range, or a direct URL reference whose origin another declaration does not share. A range and a pin that satisfies it, as pip-tools, uv and lock files write them, do not conflict. Ranges are not compared with each other; declarations under different markers, such as the platform splits `uv export` writes, or in different `[project.optional-dependencies]` groups, such as uv's `cpu` and `cu121` extras, are not compared; the extras a requirement names, such as `openai[datalib]`, are not compared; and a declaration that cannot be parsed is reported as a collection failure instead. The comparison takes time linear in the size of the files read; a declaration with a version longer than 128 characters is recorded but not compared. Each declaration from a requirements file or the `[project]` table is recorded, redacted, so a change to its version, marker, extras or URL scheme, host or port reaches `diff`; `[tool.poetry]` dependencies are covered by a separate entry. A direct URL or VCS reference containing `//` keeps only its scheme, host and port, taken from the whole parsed URL so that a quote inside it cannot leave the rest behind, and a line that cannot be parsed is recorded only up to the word that holds its first `//`, because a path or query can carry credentials; a change within the same origin therefore does not reach `diff`. Such a URL without a host is replaced entirely, and a reference written without `//`, such as `file:/path`, or a relative path is recorded as written. Options are split from a requirement on spaces only, as pip does, so a tab or another space character stays inside the requirement. Includes, constraints files, editable installs and URL, VCS and path requirements are covered by a separate entry; the targets of references are still not fetched.
- End a command with a plain error, not a Python traceback, when its output path cannot be written safely: a symbolic link on the way, a missing directory, or a directory as the target. Other failures, such as a permission error or a full disk, are reported by the system's message, without the path. This applies to the `-o`/`--output` file of every command and to `init --path`; `runtime keygen` still ends such a failure with a traceback. `init --path` follows the same rule instead of writing through a symlinked directory, `vex` and `advisories` also refuse a second name for their input, such as a hard link, and no command replaces a device, FIFO or socket named as its output. `..` in an output path now steps to the real parent directory, as the operating system resolves it, instead of being refused.
